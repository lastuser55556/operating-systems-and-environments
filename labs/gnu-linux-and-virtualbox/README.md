## 1. Проект GNU

GNU — проект по созданию свободной Unix-подобной операционной системы. Название расшифровывается как **GNU's Not Unix**. Проект объединяет множество программ: командные оболочки, компиляторы, системные утилиты, библиотеки и другие компоненты.

Ричард Столлман объявил о начале проекта GNU в 1983 году, а в 1985 году опубликовал «Манифест GNU». Главная идея проекта состоит в том, чтобы пользователь мог запускать, изучать, изменять и распространять программы. К началу 1990-х годов GNU предоставлял почти все основные компоненты операционной системы, но проекту не хватало готового ядра.

## 2. Ядро Linux и система GNU/Linux

Linux — ядро операционной системы. Ядро работает между оборудованием и прикладными программами. Оно управляет процессорным временем, оперативной памятью, устройствами, файловыми системами и запуском процессов.

Одно ядро не образует полноценную пользовательскую систему. На практике его используют вместе с программами и библиотеками GNU, графической средой и прикладными программами. Такое сочетание называют **GNU/Linux**.

## 3. Дистрибутивы GNU/Linux

Дистрибутив GNU/Linux — готовая операционная система, собранная вокруг ядра Linux. Обычно в дистрибутив входят:

- ядро Linux;
- системные библиотеки и утилиты GNU;
- менеджер пакетов и репозитории программ;
- установщик системы;
- графическая подсистема и рабочее окружение;
- документация и набор приложений;
- иногда проприетарные драйверы и кодеки.

Дистрибутивы различаются назначением, способом обновления, набором программ и моделью поддержки. Одни разрабатывают компании, другие поддерживает сообщество. Каталог дистрибутивов доступен на [DistroWatch](https://distrowatch.com/).

## 4. Популярные дистрибутивы

| Дистрибутив | Краткая характеристика |
|---|---|
| **Debian** | Один из старейших дистрибутивов. Известен стабильностью и большим набором пакетов. |
| **Ubuntu** | Основан на Debian, разрабатывается компанией Canonical. Используется на домашних компьютерах и серверах. Основное окружение рабочего стола — GNOME. |
| **Linux Mint** | Основан на Ubuntu и ориентирован на домашнее использование. Интерфейс Cinnamon привычен многим пользователям Windows. |
| **Arch Linux** | Предоставляет минимальную базовую систему и обновляется по модели Rolling Release. Пользователи могут устанавливать пакеты из AUR. |
| **Manjaro** | Основан на Arch Linux, но предлагает более готовую к работе систему и несколько графических окружений. |
| **Red Hat Enterprise Linux** | Коммерческий дистрибутив с длительной поддержкой, рассчитанный прежде всего на организации и серверы. |
| **Fedora** | Свободный дистрибутив, связанный с экосистемой Red Hat. Новые технологии часто появляются в Fedora раньше, чем в RHEL. |
| **CentOS Stream** | Дистрибутив экосистемы Red Hat, находящийся между Fedora и будущими выпусками RHEL. |
| **openSUSE** | Подходит для домашнего и профессионального использования. Имеет стабильную ветку Leap и постоянно обновляемую ветку Tumbleweed. |

## 5. Файловая структура GNU/Linux

В GNU/Linux все файлы и каталоги образуют единое дерево. Его вершина — корневой каталог `/`. Диски и другие носители подключаются к этому дереву в точках монтирования.

![Иерархия каталогов GNU/Linux](images/linux-filesystem-hierarchy.png)

Картинка взята из учебной презентации «ОС L.pptx».

Назначение основных каталогов:

| Каталог | Назначение |
|---|---|
| `/` | Корень файловой системы. |
| `/bin` | Основные пользовательские команды. В современных системах часто является ссылкой на `/usr/bin`. |
| `/boot` | Файлы загрузчика и ядра. |
| `/dev` | Файлы устройств. |
| `/etc` | Общесистемные настройки и конфигурационные файлы. |
| `/home` | Домашние каталоги обычных пользователей. |
| `/lib` | Основные системные библиотеки и модули ядра. |
| `/media` | Точки автоматического подключения съёмных носителей. |
| `/mnt` | Временное ручное подключение файловых систем. |
| `/opt` | Дополнительные сторонние программы. |
| `/proc` | Виртуальная файловая система с данными о процессах и ядре. |
| `/root` | Домашний каталог суперпользователя `root`. |
| `/run` | Данные работающих служб, созданные после загрузки системы. |
| `/sbin` | Системные команды администратора. В современных системах часто является ссылкой на `/usr/sbin`. |
| `/srv` | Данные, которые предоставляют системные службы. |
| `/sys` | Виртуальная файловая система с информацией об устройствах и ядре. |
| `/tmp` | Временные файлы. |
| `/usr` | Большая часть пользовательских программ, библиотек и общих данных. |
| `/var` | Изменяемые данные: журналы, кэш, очереди и базы служб. |

## 6. Индексный дескриптор inode

**Inode** — структура данных файловой системы, в которой хранятся метаданные объекта. Имя файла находится в записи каталога, а эта запись указывает на номер inode. Сам inode указывает, где размещены данные файла.

Обычно inode хранит:

- тип файла и права доступа;
- идентификаторы владельца и группы;
- размер;
- время изменения и другие временные отметки;
- количество жёстких ссылок;
- адреса блоков данных на диске;
- дополнительные метаданные файловой системы.

Номер inode уникален только внутри одной файловой системы. Поэтому на разных разделах могут существовать объекты с одинаковыми номерами inode. Количество inode задаётся при создании файловой системы или определяется её внутренним устройством.

Посмотреть номер inode можно командой:

```bash
ls -li имя_файла
```

Подробные сведения об объекте показывает команда:

```bash
stat имя_файла
```

## 7. Установка VirtualBox и Ubuntu

Ниже описан один из вариантов выполнения задания: установка Ubuntu Desktop в Oracle VirtualBox.

### 7.1. Подготовка

1. Проверьте, что в BIOS/UEFI включена аппаратная виртуализация Intel VT-x или AMD-V.
2. Скачайте VirtualBox для своей основной операционной системы с [официальной страницы Oracle](https://www.virtualbox.org/wiki/Downloads).
3. Установите VirtualBox, оставив стандартные компоненты. Во время установки сетевое подключение может кратковременно прерваться.
4. Скачайте ISO-образ Ubuntu Desktop с [официального сайта Ubuntu](https://ubuntu.com/download/desktop).

### 7.2. Создание виртуальной машины

1. Откройте VirtualBox и нажмите **New / Создать**.
2. Укажите имя, например `Ubuntu`, и выберите скачанный ISO-образ.
3. Выберите тип **Linux** и подходящую версию **Ubuntu (64-bit)**, если программа не определила их автоматически.
4. Для полностью ручной установки включите **Skip Unattended Installation**. Если оставить автоматическую установку, VirtualBox заранее попросит имя пользователя и пароль.
5. Выделите ресурсы. Для учебной машины обычно достаточно 2 ядер процессора, 4 ГБ оперативной памяти и динамического виртуального диска размером 25–40 ГБ. Не выделяйте виртуальной машине больше половины ресурсов основного компьютера.
6. Проверьте итоговые параметры и завершите создание машины.

### 7.3. Установка Ubuntu

1. Выберите созданную машину и нажмите **Start / Запустить**.
2. При ручной установке выберите **Try or Install Ubuntu**, затем язык и раскладку клавиатуры.
3. Запустите установку Ubuntu.
4. В качестве диска выберите виртуальный диск. Пункт удаления данных относится только к виртуальному диску этой машины, если он выбран правильно.
5. Укажите часовой пояс, имя пользователя, имя компьютера и пароль.
6. Дождитесь окончания копирования файлов и перезагрузите виртуальную машину.
7. Если установщик попросит извлечь носитель, отключите ISO через меню **Devices → Optical Drives** и нажмите Enter.

### 7.4. Первичная настройка

После входа в Ubuntu откройте терминал и установите обновления:

```bash
sudo apt update
sudo apt upgrade -y
```

Для автоматического изменения разрешения окна, общего буфера обмена и удобной работы мыши установите **Guest Additions**:

1. В окне запущенной машины выберите **Devices → Insert Guest Additions CD Image**.
2. Откройте появившийся диск в Ubuntu и запустите установщик.
3. После установки перезагрузите гостевую систему.

Подробный пример есть в [официальной инструкции Ubuntu по VirtualBox 7](https://ubuntu.com/tutorials/how-to-run-ubuntu-desktop-on-a-virtual-machine-using-virtualbox).

## 8. Снимки виртуальной машины

### Что такое snapshot

**Снимок виртуальной машины (snapshot)** сохраняет состояние виртуальных дисков и настройки машины в выбранный момент. Если снимок сделать при работающей машине с сохранением памяти, VirtualBox может также сохранить состояние оперативной памяти. После восстановления система вернётся к сохранённому состоянию: более поздние изменения файлов, программ и настроек будут отменены.

Снимок удобно создавать перед обновлением системы, установкой драйвера или рискованным экспериментом. Он не заменяет резервную копию: снимки зависят от основной виртуальной машины и со временем занимают дополнительное место на диске.

### Как создать снимок

1. По возможности корректно выключите Ubuntu. VirtualBox поддерживает снимки работающей машины, но снимок выключенной системы обычно проще и занимает меньше места.
2. В VirtualBox Manager выберите нужную виртуальную машину.
3. Откройте раздел **Snapshots / Снимки**.
4. Нажмите **Take / Сделать снимок**.
5. Введите понятное имя, например `Чистая Ubuntu после установки`, добавьте описание и подтвердите создание.

### Как восстановить снимок

1. Выключите виртуальную машину.
2. Откройте раздел **Snapshots / Снимки**.
3. Выберите нужный снимок и нажмите **Restore / Восстановить**.
4. Если нужно сохранить текущее состояние, согласитесь создать снимок перед восстановлением.
5. Запустите машину и проверьте результат.

При восстановлении все изменения после выбранного снимка будут потеряны, если их заранее не сохранить отдельно. Удаление снимка освобождает связанные с ним данные, но VirtualBox может некоторое время объединять виртуальные диски.

Подробнее: [раздел о снимках в руководстве Oracle VirtualBox](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/working-with-vms.html#snapshots).

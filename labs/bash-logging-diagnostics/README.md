# Практическая работа: Bash, логирование и диагностика ОС

Задание: выполнить примеры из [исходного README](https://github.com/yaroslavrychikin-crypto/log_test_safe/blob/main/README.md) и предоставить подтверждение через Git.

В каталоге [`scripts/`](scripts/) находятся 16 примеров по порядку: строгий режим Bash, уровни и файлы логов, `trap EXIT/ERR`, сигналы, безопасный разбор конфига, аргументы, валидация, таймаут, сведения о системе, диски, HTTP, `flock`, скрытие секретов и итоговая диагностика.

## Выполнение

```bash
python3 labs/bash-logging-diagnostics/run_checks.py
```

Проверки реально запущены в Linux: **24/24 совпали с ожидаемым результатом**. Таблица с кодами возврата и наблюдениями: [results.md](results.md). Ошибочные варианты с ненулевым кодом являются ожидаемыми проверками `set -e`, `trap`, аргументов, валидации и блокировки. Варианты скриптов для таких проверок создаются во временном каталоге, который удаляется после запуска.

Для HTTP использован локальный тестовый сервер с ответами 200 и 500. Временные файлы, блокировки, отчёты и журналы создавались в отдельном временном каталоге. В Git сохранены результаты проверок, но не содержимое `system.txt`, которое может содержать имя машины и другую информацию окружения.

В исходные примеры внесены небольшие исправления для воспроизводимого запуска: путь блокировки в № 6, 14 и 16 можно задать переменной окружения; № 16 корректно разбирает список HTTP-адресов при изменённом `IFS` и сохраняет вывод логов после открытия блокировки. Конфиг в № 7 специально содержит строку `rm -rf /`: штатный парсер её отклоняет. Небезопасный вариант с выполнением содержимого конфига как Bash-кода не запускался.

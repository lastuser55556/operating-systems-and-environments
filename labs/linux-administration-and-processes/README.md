# Администрирование Linux — краткий конспект

## 1. Установка Linux

Рассмотрена установка на примере Debian. Для большинства дистрибутивов процесс похож: выбирают язык и регион, задают надёжные пароли для обычного пользователя и суперпользователя.

### Разметка диска

Разметку выполняют двумя способами:

- **Guided** — автоматически. Обычно подходит для большинства сценариев.
- **Manual** — вручную. Нужна, когда требуется самому определить размеры разделов или создать отдельные разделы под конкретные задачи.

При ручной разметке указывают вид раздела, файловую систему и точку монтирования. На этапе установки также выбирают необходимое программное обеспечение.

## 2. Пользователи и суперпользователь root

В Linux существуют обычные и системные пользователи.

- Обычных пользователей создаёт системный администратор. У каждого есть числовой идентификатор **UID**.
- Системных пользователей создаёт операционная система. Обычно они нужны для работы приложений.
- **root** — системный пользователь с UID 0. Он может выполнять любые операции, игнорировать права доступа и переключаться на других пользователей.

Постоянно работать с правами root не рекомендуется: это повышает угрозу безопасности и риск серьёзных ошибок, способных повредить систему.

### Управление учётными записями

Создание пользователя:

```bash
useradd [опции] пользователь
```

Основные опции `useradd`:

| Опция | Назначение |
| --- | --- |
| `-b` | базовый каталог для домашнего каталога, по умолчанию `/home` |
| `-d` | домашний каталог пользователя |
| `-c` | комментарий к учётной записи |
| `-e` | дата блокировки учётной записи |
| `-f` | блокировка учётной записи сразу после создания |
| `-g` | основная группа пользователя |

Удаление пользователя:

```bash
userdel [опции] пользователь
```

- `-f` — принудительно удалить учётную запись и домашний каталог.
- `-r` — удалить пользователя вместе с домашним каталогом и почтовым ящиком.

### Смена пользователя и sudo

`su` (*switch user*) позволяет перейти под root или другого пользователя, зная пароль. Команды, выполненные через `sudo`, записываются в `/var/log/auth.log`.

Чтобы дать пользователю права sudo, его добавляют в группу `sudo`:

```bash
usermod -aG sudo имя_пользователя
```

`sudo` запускает отдельную команду с привилегиями суперпользователя без открытия новой оболочки.

Файл **sudoers** содержит правила привилегий. Его редактируют только командой `visudo`.

```text
root  ALL = (ALL:ALL) ALL
%sudo ALL = (ALL:ALL) ALL
```

В первой строке указываются: имя пользователя, все хосты, все пользователи, все группы и все команды. Вторая строка разрешает пользователям группы `sudo` запускать любые команды.

### Пароли и системные файлы

Пароль меняют утилитой:

```bash
passwd [опции] пользователь
```

Основные опции:

| Опция | Назначение |
| --- | --- |
| `-d` | удалить пароль |
| `-e` | сделать пароль устаревшим |
| `-i` | отключить аккаунт через заданное число дней после устаревания пароля |
| `-l` | запретить вход в систему |
| `-n` | минимальное число дней между сменами пароля |
| `-x` | максимальный срок использования пароля |

Файл `/etc/passwd` — текстовая база данных учётных записей. Каждая строка содержит семь полей: имя пользователя, поле пароля, UID, GID, GECOS, домашний каталог и оболочку входа. В современных системах поле пароля обычно содержит `x`, а хеш пароля хранится в `/etc/shadow`.

`/etc/shadow` содержит зашифрованные пароли и данные о сроках их действия: дату последней смены, минимальный и максимальный срок, срок предупреждения, дату отключения учётной записи и резервное поле.

## 3. Права доступа

Каждый файл в Linux принадлежит одному пользователю и одной группе. Просмотреть владельца, группу, тип и права можно командой:

```bash
ls -l [путь к файлу]
```

Первый символ в выводе обозначает тип объекта:

| Обозначение | Тип |
| --- | --- |
| `-` | обычный файл |
| `d` | директория |
| `l` | символическая ссылка |
| `c` | устройство символьного ввода-вывода |
| `b` | устройство блочного ввода-вывода |
| `p` | FIFO, связь между процессами |
| `s` | сокет |

Права имеют значения:

- `r` — чтение;
- `w` — запись;
- `x` — исполнение.

Для файла `r` разрешает чтение данных, `w` — изменение содержимого, `x` — запуск. Для каталога `r` разрешает просмотр содержимого, `w` — создание и удаление объектов, `x` — вход в каталог.

Владельца и группу меняют командами:

```bash
chown [опции] user1 file1
chgrp [опции] group1 file1
```

### chmod и числовые режимы

`chmod` меняет права доступа:

```bash
chmod +x file       # сделать файл исполняемым для всех
chmod ug+w file     # разрешить запись владельцу и группе
chmod o-w file      # запретить запись остальным
chmod ugo+rwx file  # разрешить чтение, запись и исполнение всем
```

Обозначения пользователей: `u` — владелец, `g` — группа, `o` — остальные. Дополнительное обозначение `s` связано с выполнением от имени root.

Числовой синтаксис использует восьмеричные значения:

| Число | Режим |
| --- | --- |
| 0 | `---` |
| 1 | `--x` |
| 2 | `-w-` |
| 3 | `-wx` |
| 4 | `r--` |
| 5 | `r-x` |
| 6 | `rw-` |
| 7 | `rwx` |

### SUID, SGID, sticky bit и umask

- **SUID** (*Set User Identifier*) временно даёт процессу права владельца файла.
- **SGID** (*Set Group Identifier*) даёт права группы-владельца файла; файлы, созданные в каталоге с SGID, получают группу этого каталога.
- **Sticky bit** позволяет удалить файл только его владельцу или владельцу каталога.

При создании файла процесс обычно запрашивает права `0666`. Значение **umask** уменьшает эти начальные права до более безопасных. В Linux типичное значение по умолчанию — `0022`.

## 4. Мониторинг Linux

Мониторинг помогает оценивать работоспособность и производительность системы, вовремя реагировать на проблемы и безопасно вносить изменения. Надёжная система мониторинга визуализирует данные и предупреждает о неполадках.

Основные утилиты:

| Команда | Назначение |
| --- | --- |
| `df` | сведения о файловых системах |
| `du` | объём дискового пространства, занятый файлами и каталогами |
| `free` | свободная и используемая оперативная память |
| `iostat` | статистика ввода-вывода устройств и разделов |
| `mpstat` | статистика по процессорам и ядрам |
| `vmstat` | память, диски, ядро, переключения контекста и процессор |
| `w` | краткая сводка о работающих пользователях |
| `htop` | процессы и ресурсы в реальном времени |

Полезные параметры:

- `df -h` — размеры в удобочитаемом виде; `df -T` — тип файловой системы; `df -t ext4` — только ext4.
- `du -a` — объём всех файлов; `du -b` — размер в байтах; `du -c` — итоговый размер.
- `free -b`, `free -k`, `free -m`, `free -g` — вывод в нужных единицах; `free -h` — удобочитаемый формат.
- `iostat -c` — только CPU; `iostat -d` — устройства; `iostat -p` — устройство и разделы; `iostat -x` — расширенная статистика.
- `mpstat -A` — вся доступная информация; `mpstat -P ALL` — все ядра; `mpstat -P 0` — конкретное ядро.
- `vmstat -a` — активная и неактивная память; `vmstat -f` — количество задач с загрузки; `vmstat -d` и `vmstat -D` — статистика дисков.
- `w -h` — без заголовка; `w -s` — сокращённый формат; `w -i` — IP-адрес вместо имени хоста.

В `htop` отображаются нагрузка на каждое ядро, память (**Mem**), процессы (**Task**), файл подкачки (**Swp**), средняя загрузка (**Load average**) и время работы системы (**Uptime**).

## 5. Конфигурация сети

Цель настройки сети — подключить компьютер или сервер к сети через конфигурационные файлы и консольные утилиты, без графического интерфейса. При ручной настройке статического адреса задают:

- IP-адрес;
- маску подсети;
- IP-адрес шлюза;
- IP-адрес DNS-сервера.

### Основные понятия

**IP-адрес** — уникальный адрес машины из четырёх десятичных чисел, разделённых точками. Частные диапазоны:

- `10.0.0.0–10.255.255.255/8`;
- `172.16.0.0–172.31.255.255/12`;
- `192.168.0.0–192.168.255.255/16`.

**Маска подсети** определяет, какая часть IP-адреса относится к сети, а какая — к узлу. Например, адрес `192.168.0.2` с маской `255.255.255.0` находится в подсети `192.168.0.0`.

**Шлюз** — адрес машины, через которую осуществляется связь с внешними сетями. В изолированной сети и на петлевом интерфейсе шлюз не нужен.

**DNS-сервер** преобразует имена хостов в IP-адреса.

Для поиска сетевых интерфейсов используют:

```bash
dmesg | grep eth
lspci | grep Ethernet
```

### Файлы конфигурации

| Файл или каталог | Назначение |
| --- | --- |
| `/etc/network/interfaces` | основной файл настройки интерфейсов в Debian/Ubuntu |
| `/etc/hosts` | соответствия IP-адресов и имён хостов |
| `/etc/resolv.conf` | параметры разрешения имён |
| `/etc/nsswitch.conf` | порядок использования служб имён |
| `/etc/sysconfig/network-scripts` | конфигурация сети в RedHat и SUSE |
| `/etc/netplan/*.yaml` | настройка сети через Netplan в Ubuntu 18.04 и новее |

Петлевой интерфейс называется `lo` и по умолчанию имеет адрес `127.0.0.1`. Его можно увидеть через `ifconfig`.

В `/etc/resolv.conf` при наличии локального DNS-кэша может использоваться строка:

```text
nameserver 127.0.0.1
```

В `/etc/nsswitch.conf` строка `hosts` отвечает за преобразование имён хостов. Источник `files` означает использование соответствующего системного файла, например `/etc/hosts`.

В системах RedHat/SUSE каталог `/etc/sysconfig/network-scripts` содержит конфигурационные файлы интерфейсов и скрипты `ifup`/ `ifdown`; `ifcfg-*` описывает интерфейсы. В `/etc/sysconfig/network` могут храниться имя хоста, основной шлюз и DNS-серверы.

**Netplan** использует YAML-файлы в `/etc/netplan/`. Формат YAML зависит от правильных отступов: неверное число пробелов приводит к ошибке `expected mapping`.

Перезапуск сети:

```bash
sudo netplan apply
sudo systemctl restart network
```

### Утилита ip

Команда `ip` управляет сетевыми интерфейсами, адресами, маршрутами и ARP-кэшем. Она показывает петлевой адрес и фактический адрес в локальной сети.

Полезные команды:

```bash
ip -s -h a              # статистика трафика в удобном виде
sudo ip link set ens33 down
sudo ip link set ens33 up
ip monitor              # события интерфейсов в реальном времени
```

`ip monitor` отображает добавление и удаление маршрутов, изменения IP-адресов и состояние сетевых устройств.

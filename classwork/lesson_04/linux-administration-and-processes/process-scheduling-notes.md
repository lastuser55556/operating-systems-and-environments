# Конспект: процессы, потоки и планирование процессов

## 1. Процессы и потоки

**Процесс** — программа, находящаяся в стадии выполнения.

Основные функции ОС по управлению процессами и потоками:
- создание и уничтожение процессов;
- планирование процессов — распределение процессорного времени;
- выделение необходимых системных ресурсов;
- обмен данными между процессами;
- синхронизация процессов и потоков.

**Поток** — единица выполнения внутри процесса. Потоки появились как средство распараллеливания вычислений. Процесс рассматривается как заявка на ресурсы, а процессорное время выделяется потокам. В простейшем случае процесс содержит один поток.

### Преимущества потоков
- создание потока требует меньше накладных расходов, чем создание процесса;
- поток создаётся быстрее;
- потоки одного процесса могут взаимодействовать через общую память без обращения к ОС;
- использование потоков может повысить производительность программы.

## 2. Состояния потоков

Основные состояния:
- **выполнение** — поток непосредственно выполняется процессором;
- **готовность** — поток готов выполняться, но ожидает процессор;
- **ожидание** — поток заблокирован до наступления определённого события.

Типичные переходы:
1. поток выбран на выполнение;
2. поток ожидает завершения ввода-вывода;
3. ввод-вывод завершён — поток снова готов;
4. поток вытеснен планировщиком.

## 3. Создание процесса

Процесс может создаваться при:
- загрузке системы;
- системном вызове работающего процесса;
- запросе пользователя.

Создание процесса включает:
1. создание описателя процесса;
2. создание как минимум одного потока выполнения;
3. загрузку кода и данных программы с диска в оперативную память.

**Дескриптор процесса** содержит информацию, необходимую ядру на протяжении жизненного цикла процесса: состояние, расположение образа процесса, приоритеты, идентификатор пользователя, сведения о родственных процессах и др.

**Контекст процесса** содержит данные, необходимые для продолжения выполнения с прерванного места: регистры процессора, открытые файлы, сведения о незавершённых операциях ввода-вывода и др.

## 4. Планирование и диспетчеризация

**Планирование** включает:
- выбор потока из очереди готовых;
- определение момента смены текущего активного потока.

Планирование бывает:
- **статическое** — решения принимаются заранее, работа идёт по расписанию;
- **динамическое** — решения принимаются во время работы системы с учётом текущей ситуации.

**Диспетчеризация** — реализация решения планировщика:
1. сохранение контекста текущего потока;
2. загрузка контекста выбранного потока;
3. запуск нового потока.

### Когда происходит перепланирование
- закончился выделенный задаче интервал времени;
- задача запросила ввод-вывод или занятый ресурс;
- задача освободила ресурс;
- завершилась операция ввода-вывода;
- возникло внутреннее прерывание из-за ошибки.

## 5. Алгоритмы планирования

### Невытесняющее планирование
Активный поток выполняется, пока сам не передаст управление ОС.

### Вытесняющее планирование
Решение переключить процессор на другой поток принимает ОС.

### Квантование
**Квант** — ограниченный непрерывный интервал процессорного времени, который поочерёдно предоставляется потокам.

Слишком маленький квант приводит к частым переключениям и снижению производительности. Слишком большой может увеличить время ответа интерактивной системы.

### Приоритетное планирование
**Приоритет** — число, характеризующее степень привилегированности потока при использовании ресурсов ОС.

Приоритеты бывают:
- **фиксированные** — не меняются за время существования потока;
- **динамические** — могут изменяться потоком, пользователем или ОС.

При относительных приоритетах приоритет учитывается при выборе из очереди готовых. При абсолютных активный поток может быть прерван при появлении готового потока с более высоким приоритетом.

Возможен смешанный подход: **квантование + приоритеты**.

## 6. Планирование в Linux

В материалах выделены три класса потоков:
1. потоки реального времени FIFO;
2. потоки реального времени с циклической очередью;
3. потоки разделения времени.

Указано 140 уровней приоритета: 0–99 для потоков реального времени и 100–139 для обычных потоков. Для обычных потоков используется значение **nice**, связанное со статическим приоритетом.

## 7. Алгоритмы для разных типов систем

### Пакетные системы
**FIFO (первый пришёл — первым обслужен)**:
- достоинства: простота и справедливость.

**Кратчайшая задача — первая**:
- сначала запускается самая короткая задача;
- уменьшает среднее оборотное время;
- требует заранее знать время выполнения задач.

### Интерактивные системы
Критерий эффективности — удобство работы пользователя.

Используются:
- циклическое планирование (квантование);
- приоритетное планирование;
- самый короткий процесс — следующий;
- гарантированное планирование;
- лотерейное планирование;
- справедливое планирование.

При гарантированном планировании отслеживается реально полученное процессом процессорное время относительно положенного ему времени.

При лотерейном планировании процессам выдаются «билеты», а ресурс получает обладатель случайно выбранного билета.

При справедливом планировании учитывается доля процессорного времени, выделенная пользователю.

## 8. Системы реального времени

Главный критерий — способность выдерживать заданные интервалы между запуском программы и получением результата.

Системы бывают:
- **жёсткие** — нарушение временных ограничений приводит к критическим последствиям;
- **гибкие** — нарушение графика нежелательно, но допустимо.

Задачи могут быть:
- **периодическими** — моменты возникновения можно определить заранее;
- **спорадическими** — моменты запросов заранее неизвестны.

Для набора задач используются:
- `pi` — период;
- `di` — предельный срок;
- `ci` — требуемое время выполнения;
- `μ` — коэффициент использования процессора.

Для задачи: **μi = ci / pi**.

Для системы с `k` процессорами необходимое условие: **Σ(ci / pi) ≤ k**.

### Алгоритм Лью — Лейланда
Для жёсткой однопроцессорной системы: задача с самым коротким периодом получает наивысший приоритет, а с самым большим периодом — наименьший.
